## Личные инструкции

- Если в промпте есть очевидная опечатка и замысел пользователя однозначен, исправляй её 
  автоматически и продолжай работу без уточняющего вопроса. Не сообщай об исправлении отдельно. 
  Уточняй только если опечатка допускает несколько трактовок и нельзя уверенно определить нужную.

## Инкрементальная реализация

Важнее сохранить полезный прогресс на диске, чем составить подробный план.

- Работай маленькими самостоятельно полезными шагами по циклу
  `осмотреть → реализовать → проверить → зафиксировать`; не откладывай правки до полного
  понимания задачи. После каждого шага репозиторий компилируется, узкие проверки зелёные.
- Не изучай кодовую базу долго перед первыми правками; углубляйся, только когда этого требует
  текущий шаг. Ритм — по фазе работы, не по таймеру: первый осмысленный diff появляется рано.
- Проверяй узко — сборка и тесты только затронутого модуля, без лишних проверок.
- В worktree фонового агента фиксируй чекпоинты `wip:`-коммитами, в конце объединяй их.
- Если довести до конца не выходит, оставь максимально полезную частичную реализацию.

## Правила Kotlin, Compose, KMP, Android

Файлы правил Kotlin, Compose, KMP и Android в rules/ — это продукт, который данный репозиторий 
распространяет в проекты-потребители; здесь они не подгружаются заранее. Прежде чем читать, 
редактировать или сверять один из этих файлов правил, вызови инструмент `list` MCP-сервера 
cuckcoder, чтобы увидеть все имена правил, затем `get_rule`, чтобы получить те из них, которые 
относятся к текущей задаче.
