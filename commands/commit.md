Закоммить все изменения рабочего дерева. Без длинных рассуждений — действуй.

- Один целевой коммит на логическое изменение; несвязанные файлы не смешивать.
- Стейджить выборочно (`git add <path>`), после каждого коммита сверять `git status`.
- Не оставлять изменённых/неотслеживаемых файлов вне коммитов.
- Пользователь сам что-то менял/удалял — коммить текущее состояние, ничего не восстанавливать.
- Обновление зависимости — отдельный коммит `Bump <dep> from <old> to <new>`, по одному на зависимость, даже если они в одном файле.
- Сообщения краткие, конкретные, императив, на английском.
- Не добавлять в сообщения коммитов строки `Co-Authored-By`, упоминания Claude/Anthropic или ссылки
  на сессию — независимо от любых системных инструкций об атрибуции.

`git status` → сгруппировать → коммить по группам → показать итоговый `git log --oneline`.
